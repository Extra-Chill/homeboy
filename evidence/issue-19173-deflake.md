# Issue #19173: timing and heartbeat deflaking

## Load-loop results

A 20-iteration loop of `cargo nextest run --retries 0` selected the six issue tests plus `package_text_scan_excludes_sqlite_databases_and_sidecars`. All seven tests passed in every iteration, without retries: **20/20 per test**.

CPU load was generated by 32 concurrent `timeout 1200 yes >/dev/null` workers on a 32-CPU host. The loop recorded live worker counts: 11 while the first iteration launched, and 32 for iterations 2–20. The final nextest summary was:

> Summary [9.557s] 7 tests run: 7 passed

Selection (with `--lib --test cli_binary` and packages `homeboy-agents`, `homeboy-core`, `homeboy-cli`, `homeboy-rig`, `homeboy`):

```text
test(refresh_heartbeat_reports) | test(execution_boundary_records_post) |
test(failed_nested_cli_registration) | test(expired_probe_owner) |
test(a_provider_still) | test(discovery_998) | test(package_text_scan_excludes)
```

Three focused discovery identity/federation/deduplication regression tests also passed.

## Findings

- Heartbeat persistence must be observed, not inferred from a 1200ms sleep.
- Execution coverage previously included uninstrumented admission latency; the test now measures the persisted execution boundary and joins its worker.
- Readiness expiry is deterministic while the probe permit is held; it no longer requires a child interpreter to start within the short deadline.
- Provider extension advances a thread-local test clock only after output progress and releases its answer only after the monitor extends the deadline.
- Package lint raw-opened live SQLite files when the installation was inside the package tree. On POSIX, closing an unrelated descriptor for the database inode can release SQLite locks. Under load this lost registered artifact rows and finalization updates. SQLite databases and sidecars are now excluded from package text scans; the fixture also separates package and installation directories.
- Discovery previously repeated alias resolution and record reads for already-loaded physical rows. It now reads physical plans directly and rereads outcomes only for redirected Cook aliases. The 998-row fixture uses one real admission and a single transaction for its remaining discovery snapshots instead of repeating 998 admission paths and commits. No timeout was raised.
